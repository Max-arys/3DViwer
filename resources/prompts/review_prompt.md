## 5. КРИТЕРИИ ПРОВЕРКИ

1. Стиль и форматирование

   Отступы — 2 или 4 пробела (консистентно по файлу), без табуляций.

   Длина строки ≤ 100 символов.

   Имена классов/структур: PascalCase.

   Имена функций/методов: консистентность в файле — либо PascalCase, либо snake_case. (Допускается смешение, если snake_case используется для свободных функций, имитирующих STL).

   Имена переменных: snake_case.

   Имена констант: kPascalCase или UPPER_SNAKE_CASE (на выбор команды).

   Запрещено объявление нескольких переменных в одной строке (из-за неоднозначности int* a, b;).

   Измеримо: количество нарушений стиля ≤ 3 на 100 строк кода.

2. SRP (Single Responsibility)

   Функция не длиннее 40 логических строк ИЛИ имеет цикломатическую сложность < 7.

   Класс не длиннее 400 строк или не более 10 публичных методов.

   У функции/класса ровно одна причина для изменения.

   Измеримо: каждая функция/класс имеют ровно одну причину для изменения.

3. Нейминг (читаемость)

   Нет однобуквенных имён (кроме i, j, k в коротких циклах ≤5 строк).

   Нет магических чисел — только именованные константы или constexpr.

   Длина имени от 3 до 30 символов (кроме счётчиков).

   Запрещены имена: tmp, data, var, a, b, c вне циклов.

   Булевы переменные с префиксом is_, has_, can_, should_.

   Измеримо: 100% «говорящих имён» — каждый идентификатор явно отражает смысл.

4. DRY (отсутствие дублирования)

   Одинаковый блок кода (≥4 одинаковых строк) не повторяется.

   Общая логика вынесена в отдельную функцию.

   Измеримо: 0 повторяющихся блоков кода.

5. Управление памятью и RAII

   **Жесткое правило C++23:** Нет ни одного вхождения оператора `new` или `delete`. Даже в фабриках должен использоваться `std::make_unique` / `std::make_unique_for_overwrite`. Для placement-new допустим только вызов `std::construct_at`.

   Классы, управляющие ресурсами, должны соблюдать Rule of 5 ИЛИ Rule of 0 (если все члены RAII-совместимы).

   Нет утечек памяти во всех ветках выполнения.

   Измеримо: 0 вхождений `new` / `delete`, 0 потенциальных утечек.

6. const-корректность

   Все методы, не меняющие состояние, помечены `const`.

   Параметры больших типов передаются как `const T&` (или `T` для move-only типов).

   Нет C-стилевых приведений типов (только `static_cast` / `dynamic_cast` / `const_cast`).

   Переменные, которые не должны меняться после инициализации, помечены `const`.

   Измеримо: 100% методов, которые могут быть `const` — помечены `const`.

7. Обработка ошибок и безопасность

   Нет неинициализированных переменных.

   Индексы массивов/векторов проверяются перед доступом или используется `.at()`.

   `nullptr` / `std::optional` / `std::expected` проверяется перед разыменованием или доступом к значению.

   Все внешние вызовы (аллокации, ввод-вывод, парсинг) имеют обработку ошибок. **Приоритет C++23:** Для ошибок без исключений использовать `std::expected<T, E>`.

   Измеримо: все пути выполнения безопасны при некорректных входных данных.

8. Отсутствие мёртвого и закомментированного кода

   Нет закомментированных блоков кода (удалить перед мержем).

   Нет недостижимого кода (`return` после `return`, `if constexpr (false)`).

   Нет `#if 0 ... #endif` без явного комментария с причиной и сроком удаления.

   Измеримо: 0 строк закомментированного кода, 0 недостижимых фрагментов.

9. Тестируемость и отсутствие глобального состояния

   Нет мутабельных глобальных переменных (кроме `constexpr` или `inline static const`).

   Статические локальные переменные допустимы для паттерна Meyers Singleton, **а также `static constexpr` переменные внутри функций для кеширования compile-time вычислений**. В обоих случаях требуется комментарий с пояснением.

   Зависимости передаются через параметры (Dependency Injection), а не создаются жестко внутри метода (`std::make_unique` внутри функции-члена — нарушение, если это не фабричный метод класса).

   Измеримо: 0 глобальных мутабельных переменных, 100% зависимостей инъектируются.

10. Современный C++23 и производительность (КРИТИЧЕСКИЙ КРИТЕРИЙ)

    Данный раздел полностью ориентирован на возможности ISO C++23.

    **Move-семантика и RVO:**
    - Move-конструкторы и move-операторы присваивания помечены `noexcept`.
    - Запрещено использование `std::move` для возвращаемого локального значения (ломает NRVO).
    - Разрешено `return auto(local_var);` для явного decay-copy, если NRVO невозможно.

    **Compile-time вычисления:**
    - Функции, которые могут быть вычислены на этапе компиляции, помечены `constexpr` или `consteval`.
    - Проверка `if consteval` используется для разделения runtime и compile-time веток.
    - Разрешено и поощряется использование `std::vector` и `std::string` в `constexpr` контексте (фича C++23).

    **Обработка данных и ошибок (Monadic operations):**
    - Вместо `if (opt.has_value())` использовать цепочки: `opt.and_then(...).or_else(...).transform(...)`.
    - Для `std::expected` применять аналогичные монадические операции: `.and_then()`, `.or_else()`, `.transform()`, `.transform_error()`.

    **Итерация и диапазоны (Ranges v3 / C++23):**
    - Запрещены циклы вида `for (int i = 0; i < vec.size(); ++i)`, где нужен только доступ к элементам. Использовать range-based for.
    - Если нужен индекс, использовать `for (auto [i, val] : vec | std::views::enumerate)`. Ручной счетчик `int i = 0` — грубая ошибка.
    - Использовать `std::views::zip` вместо параллельной итерации по нескольким контейнерам с индексами.

    **Новые типы и утилиты C++23:**
    - `std::expected<T, E>`: Используется для функций, которые могут вернуть ошибку. Не использовать `std::optional` с пустым значением как признак ошибки.
    - `std::mdspan`: Используется для безопасной работы с многомерными данными вместо `T**` и ручных вычислений смещений.
    - `std::unreachable()`: Ветки `default` в `switch`, которые теоретически невозможны, должны завершаться `std::unreachable();` для помощи оптимизатору.
    - `auto(x)` decay-copy: Используется для явного копирования prvalue в заголовках циклов или лямбдах.

    **Атрибуты C++23:**
    - `[[assume(expression)]]`: Используется для подсказок компилятору в критичных к производительности участках (только при наличии бенчмарков).

    Измеримо: Код использует идиомы C++23. Отсутствуют конструкции, замененные в стандарте 23 (например, ручные индексы заменены на `enumerate`).
